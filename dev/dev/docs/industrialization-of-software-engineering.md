## Industrialization of Software Engineering

- Programming is the pursuit of one person to solve a problem how they understood it to be. When programmers moved from solving "tame problems" to "wicked problems" programming became software engineering. My favorite articulation of the difference between programming and software engineering comes from Titus Winters: "software engineering is programming plus people plus time."
- As we tackled more wicked problems using software, software became valuable. And, we built tools to automate toil and standardized bespoke practices to make software engineering a profession akin to a team sport.
- At the level of a small bug fix, modern software engineering already looks like an assembly line. Tooling, environments, version control, testing practices, deployment pipelines, and review rituals are standardized across most organizations.
- Modern software engineering has mechanized certain steps—building, testing, deploying—but the pipeline as a whole remains bespoke, manual, and deeply human. Problem framing, system design, code creation, integration, and reliable operation all depend on tacit knowledge and individual judgment.
- [What remains bespoke is everything before the assembly line starts: finding and interpreting problems, diagnosing what’s actually broken, untangling dependencies and constraints, debating solutions, making trade-offs under uncertainty, turning intent into precise, actionable specifications, sequencing work into buildable units, coordinating across teams, systems, and timelines, building software and running it.]
- For the most part, writing code remains human. I like to think it is because writing code in a quiet corner is the most enjoyable aspect of software engineering-- (yes, I too use em-dashes every now and then)--the soul of software engineering, if you will.
- The real reason might actually be because we lacked a common language with computers. Outside of compiler generators and rudimentary code generators, program synthesis remain an unsolved problem in general. More specifically we don't know how to turn intent into code automatically.

- Every major technological wave turned a fixed domain into a programmable substrate. Chips made computation programmable. The internet made connectivity programmable. The web made information programmable. LLMs make intelligence programmable.
- Programmable intelligence won’t just automate the craft of writing code; it marks the beginning of industrializing the entire lifecycle of software. Code generation is the first domino.
- What does industrialized software engineering look like? Industrialized software engineering produces generative software where the primary artifact is verifiable specification and software is produced just-in-time. Systems are assembled, evolved, and operated by agents that understand intent, constraints, and context. Code generation, integration, testing, upgrades, and operations are automated and continuously optimized. Humans set architecture and governance; the system handles execution. Software becomes a dynamic interface—generated on demand, upgraded automatically, and integrated through self-organizing graphs—ushering in the era of Just-in-Time Software.
